## 1. Sac 思路 → 本项目映射

| Sac 的原则 | 在本项目的落实 |
|---|---|
| 先锁视觉，再碰 3D | 色板已锁（odyssey-visual.md）；补一张**多视角场景参考表**即可开工 |
| 多视角参考表是唯一真相源 | 参考表 = 摆放、比例、光照的唯一验收基准，`review_shots.py` 的截图全部对照它 |
| 资产分诊，不无脑生成 | 见 Phase B 分诊表：地形/海/天**程序化**，高细节道具才进 Tripo |
| 生成者/审查者分离 | Blender 出三视角截图 → 独立审查 prompt 盲评 → 不通过就迭代（循环到通过） |
| 先白模后贴图 | Tripo 里先看线框/白模，剪影不对就重生成，别急着上贴图 |
| 角色品质在绑定与动画 | 省钱路线：Mixamo 免费自动绑定 + 现成 idle/walk；不买 Auto-Rig Pro |

## 3. Phase B · 资产分诊（谁进 Tripo，谁程序化）

Sac 的规则：**按资产的下游用途选做法，不是所有东西都最高细节**。本场景的分诊结论：

| 资产 | 做法 | 档位 | 面数预算 | 理由 |
|---|---|---|---|---|
| 女巫小屋 | Tripo · Image to 3D (HD) | 高 | ≤ 15k | 视觉主角，近景 |
| 坩埚（含绿泡） | Tripo · Image to 3D (HD) | 高 | ≤ 5k | 剧情焦点，绿泡后期换自发光材质 |
| 小船 + 栈桥 | Tripo · Image to 3D（普通档） | 中 | ≤ 8k | 中景，进港构图用 |
| 旧祭坛石碑 | Tripo · Image to 3D（普通档） | 中 | ≤ 4k | 交互点，特写才看细节 |
| 玛草丛 | Tripo · Image to 3D | 低 | ≤ 1.5k ×3 变种 | 可采集物，小且多 |
| 乔木 | Tripo · Image to 3D | 低 | ≤ 3k ×3 变种 | 复制摆放，不追求单棵精度 |
| **喀耳刻** | Tripo · **Multi-View to 3D + Smart Mesh** | 游戏档 | ≤ 30k | 四视图输入，需绑定 |
| **无名旅人** | 同上 | 游戏档 | ≤ 30k | 同上 |
| 岛体地形 | **Blender 程序化**（圆盘 + 噪声位移） | — | ≤ 20k | 形状简单，程序化可控且贴色板 |
| 海面 | **Three.js shader** | — | 1 平面 | 波动 + 近岸渐变，"近岸浅→外海深"已实现过 |
| 天空 | **Three.js 渐变穹顶** | — | 无 | 黄昏金色逆光方向写死在光照里 |
| 草地覆盖 | **Three.js instanced 草卡** | — | 视预算 | 贴色板两档绿，破"色块感" |
| 火堆/萤火 | **粒子** | — | 无网格 | 暖橙 #e0783a，氛围担当 |

## 4. Phase C · Tripo 生成参数

| 项 | 场景道具 | 角色 |
|---|---|---|
| 模式 | Image to 3D | **Multi-View to 3D**（四视图同传） |
| 档位 | 道具按上表选 HD / 普通 | **Smart Mesh**（游戏拓扑） |
| 面数 | 按上表预算选档 | 中等档（绑定前可控） |
| 贴图 | PBR 2K | PBR 2K |
| 导出 | **glb**，+Y up | glb，T-pose |

**验收规则（Sac 的"先白模后贴图"）**：
1. 生成后先看**白模 + 线框**：剪影、结构与参考图对不上 → 直接重生成，别浪费时间调贴图。
2. 角色四视图输入时确认**四肢无粘连**，T-pose 标准度高，否则绑定阶段全还债。
3. 道具逐个过一遍 `clean_asset.py`（见 Phase D），统计面数达标才入库。

## 5. Phase D · Blender 清理与审查（自动化脚本）

两个脚本已放在 `3d/tools/`，Blender 4.x 可直接跑：

```bash
# 1) 资产清理：导入 → 合并 → 统一变换/法线 → 原点落脚底 → 按预算减面 → 导出 glb + 统计报告
blender --background --python tools/clean_asset.py -- hut.glb hut_clean.glb --target 15000 --prefix hut

# 2) 场景审查：对 assembled.glb 渲染 顶/前/侧 + 3/4 透视 四张图，喂给审查 agent
blender --background --python tools/review_shots.py -- assembled.glb shots/
```

### 审查循环（生成者/审查者分离，Sac 的核心一招）

把 `shots/` 里的 4 张截图 + A1 参考表一起发给任意视觉模型（Claude/GPT/即梦皆可）：

```
你是独立场景审查员，与搭建者不是同一方。下面是同一 3D 场景的
俯视/正视/侧视/透视截图，以及目标多视角参考图。
逐项对比：布局位置、物体比例、色调、光照方向、密度（过空/过挤）。
只报告"与参考明显不同"的问题，按 大/中/小 分级，并给出可执行的修改建议。
没有"大"级问题时，明确输出"通过"。
```

**循环纪律**：大级问题必须改完重截图再审；连审 2 轮无大问题才进入下一阶段。这条替代了"人眼反复盯屏"，是整个流程提速的关键。

### 角色绑定与动画（省钱路线）

1. Tripo 出的角色 glb → 上 **Mixamo**（免费）自动绑定 + 挑 `idle` / `walk` 两个动作，下 FBX。
2. Blender 里重定向到角色骨架（Mixamo 骨架同名，基本直落）。
3. 特殊动作（采药、交付）从最接近的 Mixamo 动作起步，用 IK 微调手部接触。
   提示词模板（给驱动 Blender 的编码 agent）：

```
用提供的 Mixamo 动作作起点，保留可用部分，用臂部 IK 控制器调整手臂姿态，
细化手指抓握与道具位置，保证手稳定贴住把手/草茎。
禁止穿模、脱手、道具悬空。完成后逐帧导出检查表。
```

## 6. Phase E · Three.js 集成

### 技术栈与目录

```
odyssey-witch/3d/
  PIPELINE.md            ← 本文档
  tools/                 ← Blender 脚本
  app/                   ← Vite + three（下一步搭建）
    index.html
    src/main.js          ← 场景组装、循环
    src/world.js         ← 岛体/海/天/草（程序化，贴色板）
    src/character.js     ← 控制器（WASD + E，第三人称跟随）
    src/dialogue.js      ← 对话 UI（复用 concept-art 立绘，四选一分支）
    public/assets/*.glb  ← clean_asset.py 的产物
```

### 场景结构与关键实现

```js
scene
├─ island        // 圆盘地形：顶点噪声位移 + 顶点色（崖面 #e0bd84→#7c5c38，草 #a8cf8e/#7d9c66）
├─ water         // 大平面 + 自定义 shader：波动 + 深度渐变（#4f8fb5 近岸 → #123c58 远海）
├─ sky           // 渐变穹顶 + 太阳方向与 #e8a84a 金色逆光绑定（光源统一左上）
├─ hemi+dir light// 半球光（天蓝/地暖）+ 平行光（金色逆光主光）+ 雾（远岛淡出）
├─ props[]       // Tripo 资产，按 A1 参考表俯视图摆放
├─ grassCards    // InstancedMesh 草卡，双档绿
├─ fire          // 粒子（暖橙 #e0783a）+ 点光源
├─ circe / player// glb 角色 + AnimationMixer（idle/walk）
└─ post          // 全屏 vignette + 胶片颗粒（odyssey-visual.md 的"胶片质感"要求）
```

要点：
- **操作心智与 2D 版一致**：WASD 移动、E 交互、Esc 关对话；相机第三人称跟随，滚轮缩放。
- **对话 UI** 直接复用 `02-喀耳刻.jpg` 立绘 + 四选一分支（买药/问路/听预言/讨活儿），文本来自 odyssey-story.md 第一章。
- **Xing 意图接入口**（为 PLAN.md 的双层架构预埋）：对话面板留一个自由输入框，
  `输入 → /v1 意图 → {category,args} → 动作`；首批接 3 个意图：`talk_to`、`gather`、`buy_item`。
  意图模型没接通前，该输入框走本地关键词匹配兜底，界面行为不变。

### 性能预算（首版）

| 指标 | 预算 |
|---|---|
| 三角面总数 | ≤ 150k |
| GLB 总体积 | ≤ 30 MB |

| 贴图 | 单张 ≤ 2K，共 ≤ 12 张 |
| 首屏可玩 | 5s 内（加载页用 `01-序章漂流.jpg`） |
